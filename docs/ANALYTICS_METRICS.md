# Definisi dan audit metrik — Performa Quiz

Dokumen ini menjelaskan rumus yang sedang berjalan setelah keputusan pemilik produk disetujui. Tidak ada data/nama siswa yang dicantumkan.

## Sumber kebenaran dan cakupan

- Sumber definisi dan ambang yang ikut ter-deploy bersama server ada di [`backend/src/config/analytics-metrics.json`](../backend/src/config/analytics-metrics.json). Backend membacanya langsung; frontend mendapat salinan tersinkron di [`frontend/lib/analytics-metrics.json`](../frontend/lib/analytics-metrics.json) melalui `npm run sync:metrics` dari direktori `backend`. Backend menetapkan `engines.node >=20`.
- Endpoint diproteksi `teacherLimit` (`backend/src/routes/analytics.route.js:13-18`) di `/api/analytics` (`backend/server.js:73`). UI saat ini meminta periode `all` untuk semua endpoint (`frontend/app/(workspace)/analytics/quiz/page.tsx:421-428`). Rentang waktu di query menggunakan `sessions.created_at`, bukan waktu jawaban (`backend/src/controllers/analytics.controller.js:9-11`).
- CTE `scoped_sessions` menetapkan populasi bersama: milik guru terautentikasi, `sessions.mode='quiz'`, dan mempunyai minimal satu respons pada poll Quiz dengan `is_correct IS NOT NULL` (`backend/src/controllers/analytics.controller.js:39-54`). Tidak ada filter status `active`/`ended`; sesi Quiz aktif dapat masuk. Sesi interaktif, sesi Quiz tanpa jawaban dinilai, dan sesi kosong tidak masuk.
- Skema menyimpan mode dan status sesi (`backend/src/db/migrations/001_schema.sql:11-30`, `backend/src/db/migrations/004_session_mode.sql:1-22`). `class_size` diwajibkan 1–500 dan data lama null diisi 30 (`backend/src/db/migrations/003_require_class_size.sql:1-12`).

## Verifikasi angka langsung terhadap API

Jalankan dari direktori `backend`:

```sh
node scripts/verify-analytics-metrics.js
```

Skrip mengambil satu guru yang memiliki data Quiz bila `ANALYTICS_TEACHER_ID` tidak ditentukan, menghitung ulang angka secara read-only dari PostgreSQL, lalu membandingkannya dengan handler API. Output tidak memuat nama atau ID siswa. Ia memeriksa sesi, siswa bernama, benar/dinilai, rata-rata skor dan kehadiran, rentang tanggal, profil/skor, aturan siswa dengan kehadiran rendah walau <3 sesi pribadinya, flag over-capacity, rate maksimal 100%, grafik, dan topik. Fixture sintetis dipakai bila kasus tepi tidak tersedia pada data aktif.

Verifikasi pada database saat implementasi: seluruh pemeriksaan bernilai **selisih 0**. Snapshot agregat yang diperiksa: 4 sesi; 30 siswa bernama; 262 benar dari 357 jawaban dinilai; skor 73,4%; kehadiran rata-rata 76,6667%; rentang 6–18 September 2026. Pemeriksaan 30 profil siswa menghasilkan 0 selisih; grafik memuat 4 sesi dan 5 topik. Ada 1 siswa nyata dengan kehadiran rendah meski memiliki <3 sesi data; API menandainya. Tidak ada sesi over-capacity pada data aktif; fixture 35 responden / kapasitas 30 memverifikasi rate 100% dan peringatan.

Untuk memverifikasi skor sesi manual, pilih sesi milik guru dan hitung `COUNT(*) FILTER (WHERE responses.is_correct = TRUE)` dibagi `COUNT(*) FILTER (WHERE responses.is_correct IS NOT NULL)`, dikali 100. Hubungkan `responses.poll_id` ke `polls.id`, saring `polls.type='quiz'`, `sessions.mode='quiz'`, dan guru pemilik sesi. Grafik hanya menampilkan sesi dengan minimal 5 jawaban dinilai. Kehadiran per sesi memakai jumlah `LOWER(TRIM(nama))` unik yang menjawab minimal satu soal dinilai dibagi `sessions.class_size`, dibatasi ke 100%.
